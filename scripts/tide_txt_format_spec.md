### tide_txt_format_spec

作業に使った前提をここにまとめます。気象庁の固定長テキスト（本リポジトリの `data_raw/jma/2026_*.txt`）を、簡易にパースできる程度の仕様として定義しています。

## 基本
- 1行 = 1日。
- 全体は「固定長（目安 136 文字）」だが、**月日部分はスペース埋め**により見かけの表記が揺れることがある（例: `26 1 1`, `2610 1`, `261231`）。
  - そのため、日付は「YYMMDD をそのまま 2+2+2 で切る」前提にしない。
- 解析できない行は原則エラー（ただし、実装側でスキップオプションを設けても良い）。

## 潮位（hourly）
- 先頭 72 文字に 24 時間分の潮位（3 文字幅 x24）。
- 符号付き整数（cm）。
- 欠損は `999`（または `9999` 等の欠損表現が混在する場合は欠損として扱う）。
- JSON 出力では hourly は **24要素固定**とし、欠損は `null` にする。

## 73文字目以降（メタ情報 + 潮汐イベント）
### 日付 + 港コード
- 73〜78 文字目（columns 73–78, 1-based）に「年下2桁 + 月日」が入る。
  - 年: `YY`（2000年代前提）
  - 月日: **可変幅（スペース埋めあり）**
    - 例:
      - `26 1 1`（1月1日）
      - `2610 1`（10月1日）
      - `261231`（12月31日）
- パース規則（推奨）：
  1) 73–78 を取り出し、右側の空白のみ除去して `d` を得る  
  2) `YY = d[0:2]`  
  3) 残り `rest = d[2:].strip()`  
     - `rest` を空白で split して2要素なら `M, D`（例: `1 1`, `10 1`）
     - 1要素なら `MMDD` とみなし `MM + DD` で切る（例: `1231`）
- 港コード（STATION）は 2 桁で、日付の後方に存在する（実装では固定位置または周辺探索で取得してよい）。
  - API の `station_code` と一致すること（master/stations.json の station_code の集合が正）。

### 潮汐イベント（高潮・低潮）
- 日付/港コードの後方にイベントが並ぶ。
- イベントは `[time4][height3]` の7文字ブロックが連結されたものとみなす。
  - `time4` は **先頭スペースを含み得る**（例: `" 338"`）。パース時に `strip()` した上で `zfill(4)` し、`HHMM` に正規化すること。
  - `height3` は潮位（cm）。
- 欠損ルール：
  - `time` が `9999` または `height` が `999` のイベントは欠損として無視。
- 高潮/低潮の割当：
  - 先頭 2 件を高潮（high）、次の 2 件を低潮（low）と扱う（不足分は空扱い）。

## エラー方針
- 日付が組み立てられない、hourly が 24 要素にならない等はエラーとする。
- ただし運用上必要なら「欠損行スキップ」オプションを実装してもよい（デフォルトはエラー停止）。

この仕様に沿って `scripts/convertTideTxtToJson.ts` で JSON に変換し、`data/tide/{year}/{station_code}.json` を出力します。
